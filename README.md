# JAEIS Podcast Studio

JAEISポッドキャストの編集担当者向け、ブラウザ内で動く音声編集アプリです。
GitHub Pagesに静的ファイルだけを公開します。音声・字幕・原稿は端末内で処理し、バックエンド・APIキー・外部への音声アップロードは不要です。

## 内蔵音源を選んで挿入（v0.8.0）

「3 音量・音楽を整える → 内蔵音源から選ぶ」で、JAEISのOP・ED・ジングルと、アプリ用に合成した標準BGMを試聴・追加できます。音楽ファイルのアップロードやAPIキーは不要です。音源一覧は折りたためます。

- OP・EDは番組の前後に追加。ジングルは「今の位置に挿入」か「原稿に合わせて使う」を選びます。原稿用に準備しただけの音源は、配置を採用するまで出力に入りません。
- BGMは会話部分に小さく重ねて繰り返します（標準初期値−26 dB）。OP・ED・ジングル中は止まり、通常のカットでは曲を再スタートしません。会話の尺・同期・字幕時刻は変えません。BGMは1曲までで、音量は手動調整できます。声量に応じた自動ダッキングではありません。
- 内蔵音源は試聴・追加・復元時にだけ読み込みます。JAEISの3音源は同じサイトから取得し、標準BGMは端末内で合成します。通信失敗時は再試行でき、編集中の内容は置き換えません。
- 保存ファイルは音源の固定ID・用途・位置・音量を記録し、復元時は内蔵音源を自動で読み込みます。収録音声や手持ちの音楽ファイルは、従来どおり選び直してください。原稿用に準備しただけの未配置ジングルは保存対象外です。
- 2026-10-09に利用者からJAEIS音源の公開同梱が権利確認済みとの回答を得ています。[音源の出所・変換・固定ID](public/music/README.md)を記録しています。収録音声・出演者の発言は同梱していません。

2026-10-09の検証：自動テスト63件（ランダムなカット150例を含むBGMの同期不変条件、保存・復元、不明IDの拒否、取得失敗後の再試行）を実施。ブラウザで同梱音源の試聴・追加・ジングルの18秒への移動・BGMの−29 dBへの変更を確認。36秒の合成音にOP・ED・ジングル・BGMを加え、収録音声だけを選び直して復元しました。復元前後のWAVはバイト単位で一致し、出力65.734558秒は会話＋挿入音の尺と一致。波形でも16秒のBGM繰り返しとジングル中のBGM停止を確認し、MP3の書き出しも確認しました。通常幅と760px幅で横はみ出しなし。全収録での音量バランスや聞き心地を保証するものではなく、公開前の試聴は必要です。


## 使い方

1. ZoomのMP4、M4A、MP3、WAVを読み込みます。混合音声と話者別ファイルは二重に重ねないでください。
2. 波形をドラッグ、または開始・終了の秒数を入力してカットします。全トラックが同じ元時刻でカットされ、取り消し・やり直しができます。
   タイムライン上部の＋／−で「全体 → 2倍 → 4倍 → 8倍 → 16倍 → 32倍」と拡大・縮小できます。倍率欄から直接選ぶこともできます。
   拡大すると選択箇所（未選択なら表示中の再生位置）が見えるように移動します。波形は表示範囲だけを描画し、長い録音や高解像度画面での32倍拡大にも対応します。カット履歴が多いときは履歴欄をスクロールできます。
3. 「不要な部分をカット」の「文字起こし」で、日本語の文字起こし、またはZoom VTT / SRT / Whisper JSONを読み込みます。Word・テキストの原稿は任意です。ある場合は「原稿で話者・ジングル位置を推定」を開き、原稿を読み込むか貼り付けます。読み取り結果を確認し、話者候補を探してください。
4. 「カット候補」で長い静かな区間・明示的なやり直し・近接する類似発言を探します。「間の残し方」は、ゆったり／自然／テンポよくから選べます。候補は自動採用しません。「範囲を調整」で元の音声と変更後のつなぎ目を聞き比べ、反映します。採用後も「カット履歴 → 微調整」から直せます。
5. 「音量・音楽を整える」で各音声の「ノイズ・声の調整」を開けます。弱めから短く試聴し、よければ「全体に反映」します。内蔵音源を選ぶか、使用許可のある音楽ファイルを追加できます。OP・ED・ジングルは前後・指定位置に挿入し、BGMは会話の下に重ねます。
   原稿に `♪ジングル♪` があれば「原稿の指定からジングルを配置」で音源を選び、挿入候補を探せます。前後の発言を聞いて「この位置に配置」を押します。採用後も音源設定の秒数を変更できます。
6. 「確認して書き出す」で試聴・確認し、MP3（192 kbps）またはWAV（44.1 kHz / 16 bit / stereo）を書き出します。確認チェックは任意で、音声を編集すると解除されます。全体の音量調整は−16 LUFS目標の単一パス処理です。
7. カット・文字起こし・素材設定は、このブラウザのlocalStorageに最新1プロジェクトを自動保存します。音声は含みません。再開時は「前回の編集を再開」を押して、画面に表示される素材を選び直します。
8. 「編集を保存」で `.studio.json` をファイルにも保管できます。別のPCでは「編集ファイルを開く」を先に押し、案内に沿って声・音楽の素材を選びます。すべて揃うと編集を復元します。

## 編集者に合わせた画面構成

主利用者は「音声編集に不慣れで、校務の合間に輪番で担当する先生」（2026-10-08ユーザー確認済み）。未実施のユーザー調査を事実として扱わず、設計上の想定を `PRODUCT.md` に記録しています。

- 上部の4工程から自由に移動し、右側にその工程の操作だけを表示します。
- 常設の素材サイドバーをなくし、中央の波形と再生操作に幅を使います。
- 検出条件・書き出しの専門設定は、必要なときに展開します。
- 初回は読み込み操作に絞り、使えない再生操作や空の履歴を表示しません。
- 見栄えのための波形・キャッチコピー・重複した手順説明は削除しました。

## モデルとプライバシー

Transformers.js 4.3.1、Whisperの多言語ONNXモデルを使用します。すべて `q8` / WASM単一スレッドで動作し、WebGPUやcross-origin isolationを必須にしません。

| モデル | モデル本体の概算容量 | 用途 |
| --- | ---: | --- |
| [Whisper Tiny](https://huggingface.co/onnx-community/whisper-tiny) | 41 MB | 動作確認・軽負荷 |
| [Whisper Base](https://huggingface.co/onnx-community/whisper-base) | 77 MB | 初期選択、軽量な日本語文字起こし |
| [Whisper Small](https://huggingface.co/onnx-community/whisper-small) | 249 MB | 精度を優先して試す選択肢 |

容量は2026-10-08確認のencoderとmerged decoderの量子化モデル合計。設定・トークナイザー・推論エンジンは別途必要です。精度・速度は音声と端末に依存します。

- モデルは文字起こしボタンを押した時だけHugging Faceから取得します。モデル・トークナイザーはブラウザにキャッシュされる場合があります。
- ONNXとFFmpegの実行エンジンは同一サイトから取得します。第三者CDNへのコード依存を避けています。
- 音声・字幕・原稿・編集内容を外部へ送りません。GitHub Pagesやモデル配信元へのアクセス自体は各提供元に記録され得ます。
- 非公開の素材・ジングル・文字起こし・プロジェクトファイルをGitに含めないでください。公開同梱の許可を確認した3音源だけを `public/music/` に置きます。テスト用実音声は `output/` に置き、公開しません。
- 音声がない箇所でWhisperが発言を生成することがあります。人名や専門用語も確認が必要です。リテイク候補は判定結果ではなく、試聴用の提案です。

## 制限

- PC版Chrome / Edge推奨。モバイルやメモリの少ない端末での長時間編集は非推奨。
- 声は8トラックまで。1ファイル350 MB / 45分、読み込み後PCM合計850 MB（音質調整後の音声も含む）、書き出しPCM650 MBまで。上限内でも端末によって処理できない場合があります。
- 音楽は20本、手持ちの音源は1本3分まで。BGMは1曲を会話中に繰り返します。声量に応じた自動ダッキングは未対応です。
- 話者別音声は同じ開始時刻として並べます。録音開始時刻が異なる場合は手動で位置を調整してください。位置変更や素材削除ではカット・字幕をリセットします。
- 声による本人確認はできません。話者候補は文字列の類似に基づきます。文字起こしや各候補には誤りがあり得るため、試聴と確認が必要です。
- 自動保存・編集ファイルは音声を含みません。元音声は保管してください。ブラウザのデータ消去・容量不足・利用制限で自動保存できない場合があります。共有PCでは他の利用者が保存済みの字幕等を参照できる場合があります。
- 自動保存は同じブラウザの最新1プロジェクトです。同時に複数のタブで別々の編集をせず、各エピソードの `.studio.json` を保存してください。操作デモは自動保存しません。再生位置・候補の判断・確認チェック・取り消し履歴は再開時に復元しません。
- 選択範囲を文字起こしした場合も字幕全体を置き換えます。現在の字幕を残したい場合は先に保存してください。
- 編集後SRTでは、カットやジングル挿入位置をまたぐ発言を省略します。単語時刻がないため、不正確な字幕を複製しないための仕様です。
- 再生と書き出しは同じ編集計画を使います。ただし音量の正規化とピーク保護は書き出し時のみです。つなぎ目には5ms、音楽の端には50msのフェードを入れます。

## 開発

### ノイズ・声の調整

- 音声ごとにノイズ低減（なし／弱め／標準／強め）、80 Hz以下の低音軽減、大きな声を抑えるコンプレッサーを設定できます。既定はすべてオフです。BGMには適用しません。咳・他人の声・反響・音割れを復元・除去する機能ではありません。
- 「原音を聞く」「調整後を試聴」はそのトラックだけを最大10秒再生します。選択範囲、または再生位置から同じ区間を聞き比べます。カット・音楽は試聴に含めません。音量スライダーは両方に適用します。
- 設定変更と全体への反映は別です。「全体に反映」後のバッファを通常再生・書き出しで共用し、「音質調整を解除」で原音に戻せます。カットと音量は保持します。未反映の設定は工程を移動すると破棄します。
- 原音・元の波形・無音検出・文字起こし入力は変更しません。保存するのは反映済みの設定だけで、再開時は元の素材から再処理します。処理中の中止・失敗では旧設定を維持します。復元中の失敗では保存内容を保持し「設定の復元を再試行」で再開できます。
- 既存のFFmpeg.wasm単一スレッド版を必要時だけ読み込みます。`afftdn`の固定ノイズフロア−50 dB・低減量6／10／16 dB・平滑化3を使用。録音のノイズ量によって効き方は変わり、全録音で同じ低減量を保証しません。声まで削れる場合は弱めるか解除してください。
- コンプレッサーはしきい値−18 dB相当・比率2:1・attack 20 ms・release 250 ms。小さな音の自動増幅はしません。全体の音量正規化は従来どおり書き出し設定で指定します。
- 長い音声は30秒ずつ、前後に1秒以上の余白を付けて処理します。FFT位置を揃え、固定したcore 0.12.10 / FFmpeg 5.1.4の`afftdn`遅延（2 × floor(sampleRate / 80)サンプル）を補正します。末尾に余白を足し、原音と同数のサンプルを取り出すことで複数トラックの同期を維持します。エンジン更新時には遅延と端点を再検証してください。

### 無音カットと微調整

- 初期設定の「自然」は2秒以上の静かな間を0.8秒残します。「ゆったり」は2.5秒以上を1.2秒、「テンポよく」は1.5秒以上を0.5秒にします。対話を急かさないための設計上の初期値で、すべての収録に最適という意味ではありません。
- 語尾側と次の発話側へ半分ずつ余白を残し、間の中央だけをカット候補にします。短い息継ぎは初期設定では対象にしません。詳細設定で検出する長さ・残す間・音量のしきい値を変更できます。採用済みのカットには遡って適用しません。
- 自動判定は各トラックの50ms RMSの低位20%付近を背景音の目安にし、6dB上（−60〜−42dBの範囲）をしきい値にします。短い音をRMSだけで見落とさないようピークも確認します。ミキサーで下げた音量ではなく元録音を判定し、ミュートしていないすべてのトラックが静かな場合だけ候補にします。50ms未満の開始位置のずれも考慮します。
- 音声認識による無音判定ではありません。極端な小声・呼吸・音楽・雑音を完全には区別できません。候補が少ない場合も、しきい値を上げる前に波形と試聴で確かめてください。
- 微調整は開始・終了それぞれの前後1.5秒を、元音声のサンプルから拡大表示します。赤い側が除去範囲です。0.05秒ずつ動かすボタンと、0.01秒刻みの秒数入力があります。波形の縦方向の拡大は音量に影響しません。
- 「変更後のつなぎ目を聞く」は未反映の範囲で試聴し、「反映する」で同じカットを更新します。「変更をやめる」では元のカットを変更しません。反映後は取り消し・やり直し、自動保存・編集ファイルに対応し、全トラックの同期を保ちます。微調整中に別の範囲を選ぶと未反映の調整を終了します。

### 任意の原稿と話者候補

- Word（.docx）・.txt・.md・貼り付けに対応。旧Word（.doc）・PDFは未対応です。10 MB・10万文字まで。Wordは本文だけを抽出し、書式・画像・Wordコメントは取り込みません。テキストはUTF-8、BOM付きUTF-16、Shift_JISに対応します。
- `【田中先生】`、`[田中先生]`、`田中先生：本文`のような話者見出しで区切ります。「司会」を実名にしたい場合は原稿欄で書き換えられます。話者の区切りがない本文は照合対象にしません。
- `※`から始まる注釈、`＜コメントや質問等＞`、空欄記号などを発言の照合から除外します。`♪ジングル♪` は読み上げない配置指示として別に保持します。自由記述の注釈や文書のレイアウトは完全には読み分けられません。「読み取り結果を確認」で見直してください。
- 原稿の順序を強制せず、局所的な言葉の一致を照合します。小さな言い換えに対応しますが、大きく言い換えた発言・原稿外・短い相づち・複数話者に似た発言には無理に名前を付けません。複数話者が一つの字幕区間に入っていても、時刻を推測して分割しません。
- 原稿を先に読み込むと、Whisperや字幕読込の後に自動で候補を探します。原稿を後から入れた場合や書き換えた場合は「原稿から話者候補を探す」を押します。確定した話者名・元字幕の名前は再照合で上書きしません。候補を却下した区間は、対象に戻すまで再照合しません。
- 「候補」と「名前あり」は別です。再生して確定するか、話者欄へ正しい名前を入力してください。SRTには確定・入力した名前と元字幕の名前だけを書き出します。未確定の候補は音声やカット判定を変更しません。
- 原稿本文・候補・確定／却下状態は自動保存と編集ファイルに含めます。原稿を書き換えると未確定の候補を消し、発言本文を書き換えるとその発言の候補を消します。音声の時刻と発言本文を原稿で書き換えることはありません。
- Whisper JSONの`segments`とTransformers.jsの`chunks`に対応。開始・終了時刻がないJSONは受け付けません。時刻付きSRTなどで出力し直してください。`segments`内の本文が空で長さ0秒の区間だけは無視します。本文のある不正区間は削除せずエラーにします。
- 「待ってください」「すみません」などの発言と、近接する機器トラブルの発言を組み合わせて「収録中断？」も提案します。待機の一言だけ、引用や授業の逸話は対象にしません。収録の再開位置は推測で削除せず、試聴・微調整してから採用してください。意味を完全に理解する検出ではなく、見逃し・誤検出があります。

### 原稿からジングルを配置

- `♪ジングル♪`、`（ジングル）`、`【ジングル】`、`※ここでジングル`などの明示的な指定を読み取ります。通常のセリフ中の「ジングル」という単語は指示にしません。1原稿50か所までです。
- 直前・直後の文を優先し、文字起こしの隣接区間の境目を探します。少しの言い換えには対応しますが、意味理解や単語時刻の推定ではありません。原稿の順番に音声を並べ直したり、原稿にない会話を削除したりしません。
- 同じ発言が複数ある、前後が一つの字幕区間に入る、対応する発言が見つからない場合は「要確認」にします。照合した発言付近にカットがある場合も位置を手動確認します。「現在の再生位置を使う」か秒数入力で指定できます。
- 専用の「ジングル音源を読み込む」で選んだ音源は、配置を採用するまで再生・出力に含めません。未配置の音源は保存対象外です。既存のジングルを選んだ場合は、最初の採用でその音源を移動し、次の採用から複製します。
- 候補は自動採用しません。原音の前後を試聴してから配置し、「挿入後を聞く」で確認します。採用後の再照合では重複挿入せず、手動調整した位置を維持します。原稿を変更しても配置済みの音楽は移動しません。用途をOP・EDに変えた音源は原稿指定との対応を解除します。
- 配置と原稿指定の対応を自動保存・編集ファイルに含めます。同じ音源をこの機能で複数回配置した場合、再開時にはその音源を1回選ぶだけで全配置を復元します。従来の編集ファイルも引き続き読み込めます。

v0.6.0の確認（2026-10-08）：約21分の実収録・273区間の字幕と、照合検証用の抜粋原稿を用い、2か所の提案・採用・0.1秒の微調整・再照合・1音源から2配置の復元をブラウザで確認しました。未採用音源が出力尺に入らないことも確認。MP3の出力尺は元音声とジングル2本の合計に一致し、挿入位置の波形相関は各0.999以上でした。幅760pxと通常幅で横はみ出しがないことを確認しました。これは原稿全体の照合精度や全編の聞き心地を保証するものではありません。実音声・字幕・検証用原稿は公開していません。

### 実素材による検証（v0.5.1）

約20分のZoom MP4を読み込み、完成音声との波形照合から作った編集案を復元し、74件のカット・音楽2本・弱いノイズ低減・低音軽減・コンプレッサーを適用して約17分のMP3を書き出しました。74件すべてをアプリの候補検出だけで自動決定したものではありません。出力尺の一致、保存・復元した編集JSONの一致、32倍拡大と画面幅変更、音量計測、ローカル音声認識による主要なつなぎ目を確認しました。実音声・字幕・編集案は公開リポジトリに含めていません。

これは全収録・全端末での保証や、耳での全編試聴の代わりではありません。v0.8.0でBGMの重ね合わせを追加しましたが、自動ダッキング、混合音声内の話者別音量補正は未対応です。公開前の試聴・出演者確認は引き続き必要です。

## 設計・検証

- `editing.ts`: 元時刻ベースの非破壊カット、音楽を含む共通の再生・出力計画。
- `media.ts`: ブラウザ内デコード、波形・RMS、再生、WAV。
- `CutEditor.tsx`: カット境界の拡大波形・前後の試聴・微調整。
- `conversion.ts`: 遅延読み込みのFFmpeg.wasm。MP4フォールバック、MP3、ラウドネス調整。
- `voice.ts` / `voice-engine.ts` / `VoicePanel.tsx`: 保存可能な音質設定、非破壊・中止可能な音声処理、原音との短い聞き比べ。
- `asr.worker.ts`: 明示起動・中止可能なブラウザ内Whisper。日本語指定、30秒分割・5秒重複。
- `transcript.ts`: 字幕、保守的なリテイク候補、編集時刻への変換。
- `speakers.ts`: 原稿の話者区切り・注釈除外、保守的な話者候補。原稿と文字起こしは別データとして保持。
- `jingles.ts` / `JinglePanel.tsx`: 原稿のジングル指定と前後の発言から候補を提案し、確認して配置。手動調整の保持と共有音源の再利用。
- `script.worker.ts` / `script-file.ts`: タイムアウト付き別スレッドでWordの本文抽出・話者照合。Word処理のライブラリは必要時のみ取得。
- `project.ts`: バージョン付き編集ファイルの検証。
- `music-catalog.ts` / `music-library.ts` / `MusicLibrary.tsx`: 固定IDの内蔵音源、遅延取得・試聴・追加・再開時の自動復元。`music-synthesis.ts` は標準BGMのローカル合成。
- `export-audio.ts`: 共通の音声レンダリングとMP3出力。

Vitest / fast-checkで、重複カットの正規化、元音声の分割不変条件、全トラックの同期、字幕の往復、候補の誤削除防止、プロジェクト保存、WAVヘッダーを検証します。原稿については注釈除外、原稿外・曖昧な発言の保留、手動話者の保護、発言本文・時刻の不変条件、保存復元も検証します。公開するテストは人工的な原稿・字幕のみです。

無音判定は小声・短いピーク・背景音・ランダムな同期位置・ミキサー音量からの独立性を検証します。微調整では既存カットの更新、変更前のデータの保全、更新後の全トラックの同期を確認します。

音質調整では共通の再生・出力計画への反映、設定の保存復元と不正値の拒否を自動テストします。2026-10-08のブラウザ確認では、合成ステレオ音声（44.1/48 kHz、61秒）の先頭・末尾・30秒境界の時刻とサンプル数の保持を確認。ローカルの短い実音声で試聴・反映・中止・MP3/WAV出力を確認し、保存復元前後のWAVがバイト単位で一致しました。すべての録音での聞き心地を保証する検証ではありません。

依存関係の注意（2026-10-08）：Mammoth 1.13.0のCLI依存 `argparse → sprintf-js` にmoderateのDoS勧告があります。本アプリはCLIを使用せず、これらは配布するブラウザバンドルに含まれません。Word処理はタイムアウト付きWorker内で本文抽出だけを行います。依存更新時に `npm audit` とブラウザバンドルを再確認してください。
